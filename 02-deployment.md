## Deployment

Documented method used: `docker-compose.yml` + `docker-compose/setup.sh`
(`composer install`, `storage:link`, `key:generate`), plus the app's own
installation-wizard API (`wizard-step`, `finish`) in place of manual browser clicks.

Commands executed, in order:

```bash
# 0. toolchain (one-time host setup)
sudo pacman -S --noconfirm docker docker-compose
sudo systemctl start docker

# 1. fetch + baseline config (verbatim copy, no edits)
git clone https://github.com/crater-invoice-inc/crater.git crater
cd crater
cp .env.example .env

# 2. build + start (first `up --build` exceeded the 10-min client timeout,
#    so the app image build was re-run detached and polled to completion)
nohup sudo docker compose build app > /tmp/opencode/crater-build.log 2>&1 &
sudo docker compose up -d

# 3. setup.sh steps (adapted to compose v2: `docker compose exec -T app ...`)
sudo docker compose exec -T app composer install --no-interaction --prefer-dist --optimize-autoloader
sudo docker compose exec -T app php artisan storage:link
sudo docker compose exec -T app php artisan key:generate --force   # non-interactive; setup.sh's plain form aborts

# 4. database
sudo docker compose exec -T app php artisan migrate --force
sudo docker compose exec -T app php artisan db:seed --force

# 5. installer completion (exactly what the web wizard calls)
curl -X POST http://localhost/api/v1/installation/wizard-step \
  -H 'Content-Type: application/json' -H 'Accept: application/json' \
  -d '{"profile_complete":"COMPLETED"}'
curl -X POST http://localhost/api/v1/installation/finish \
  -H 'Content-Type: application/json' -H 'Accept: application/json'
```

## Authentication

- Mechanism: Laravel Sanctum Bearer tokens. Login endpoint
  `POST /api/v1/auth/login` with `{"username","password","device_name"}`.
- Valid credentials (`admin@craterapp.com` / `crater@123`, from `UsersTableSeeder`):
  → `200 {"type":"Bearer","token":"1|<42-char>"}`. [VERIFIED]
- Invalid password + `Accept: application/json`:
  → `422 {"message":"The given data was invalid.","errors":{"email":["The provided credentials are incorrect."]}}`. [VERIFIED]
  (Without the `Accept` header Laravel returns `302 → /` — standard content
  negotiation, not an app defect. All API checks below use the header.)
- Authenticated request: `GET /api/v1/auth/check` with `Authorization: Bearer <token>`
  → `200` body `1`. Without token → `401 {"message":"Unauthenticated."}`. [VERIFIED]
- Company-scoped endpoint: `GET /api/v1/bootstrap` with token + `company: 1`
  → `200` (after installer completion; see Problems §2). [VERIFIED]

No cross-company, cross-role, or privilege-escalation requests were made.

## Problems

1. **No Docker/PHP toolchain on host.**
   Error: `docker: command not found`, no PHP/Composer.
   Cause: minimal Arch workstation.
   Fix: `sudo pacman -S docker docker-compose` + `systemctl start docker`.
   Behavior change: host-level only; application untouched.

2. **`GET /api/v1/bootstrap` → 500 after migrate+seed.**
   Error: `production.ERROR: Attempt to read property "items" on null at
   app/Traits/GeneratesMenuTrait.php:11`.
   Cause: `AppServiceProvider::boot()` builds menus only when the
   `storage/app/database_created` marker exists; the marker is created by the
   installation wizard (`installation/finish`), which was bypassed by CLI seeding.
   Fix: called the app's own installer endpoints (`wizard-step` with
   `profile_complete=COMPLETED`, then `finish`) — exactly what the web wizard does.
   After that: bootstrap → 200, web `/` → 200 (was 302 to `/installation`).
   Behavior change: none beyond a normal completed installation.
   Note: after `migrate:fresh`, the marker persists on the volume while
   `finish` then 302s (`redirect-if-installed`); `wizard-step` stays 200 —
   expected installer state machine, documented for fixture scripts.

3. **`key:generate` aborts non-interactively.**
   Error: `Do you really wish to run this command? ... Command Canceled!`
   Cause: `APP_ENV=production` confirmation prompt.
   Fix: `key:generate --force` (same command setup.sh intends).
   Behavior change: fresh local `APP_KEY` only (good hygiene; avoids shipping
   the public example key).

4. **First `compose up --build` exceeded the 10-minute client timeout.**
   Cause: `php:8.1-fpm` layer pulls + `pecl install imagick` compile.
   Fix: re-ran `compose build app` detached, polled to `crater-php:latest` (1.47 GB).
   Behavior change: none.

5. **Frontend assets not built** (`public/mix-manifest.json`, `public/js|css` absent).
   Cause: `npm install && npm run ...` never run (and not needed for API research).
   Impact: web `/` returns 200 but the Vue UI may render incompletely.
   Decision: accepted — research target is the REST API; no fix applied.
   Revisit only if a phase explicitly needs the browser UI.
